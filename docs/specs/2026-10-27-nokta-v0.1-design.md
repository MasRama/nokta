# Nokta v0.1 design

Status: draft for review
Date: 2026-10-27
Scope: first release (v0.1.0), Linux on GNOME Shell 46 (Wayland)

## 1. What Nokta is

Nokta is an open-source, MacBook-style notch for the desktop. A black notch
sits on the top edge of the screen, shows what is happening (now: music and
lyrics) and opens on hover into a larger panel. The long-term target is Linux
(GNOME, then KDE and wlroots compositors), Windows and macOS, from one shared
core.

v0.1 is the smallest version the author can use every day on his own machine:

- Music: title, artist, cover, play/pause, previous, next, seek.
- Synced lyrics: the current line, following the song.
- A notch that feels good: correct shape, smooth open/close, no visible lag.

Everything else is out of scope for v0.1 (see section 11).

### Success criteria

1. Used daily on the reference machine (Zorin OS 18, GNOME Shell 46, Wayland,
   two monitors) without the desktop feeling slower.
2. Idle cost: the daemon uses no CPU while nothing plays, and stays under
   15 MB resident memory. The extension runs only the timers listed in 6.5:
   one per minute for the clock when idle, none when music is paused.
3. A tagged v0.1.0 GitHub release that another GNOME 46 user can install by
   following the README.

## 2. Architecture

Two processes, one contract.

```
Media players ──MPRIS (session D-Bus)──▶ noktad (Rust daemon)
                                            │  io.nokta.* interfaces
                                            ▼
                                   GNOME Shell extension (TypeScript → JS)
                                            │
                                            ▼
                                     the notch on screen
```

- **`noktad`**, a Rust daemon, owns all logic and all I/O: player tracking,
  cover caching, lyrics fetching and caching, configuration. It is the part
  that will be reused unchanged on other platforms.
- **The GNOME Shell extension** only draws and animates. Heavy work never runs
  inside the GNOME Shell process, because a slow extension makes the whole
  desktop stutter.
- **The contract** is a set of versioned D-Bus interfaces described as XML in
  `contracts/`. Both sides are checked against those files (section 9).

Why a separate daemon instead of doing everything in the extension: reuse on
other platforms, isolation (a daemon crash cannot take down GNOME Shell), and
review rules on extensions.gnome.org (EGO), which forbid shipping binaries
inside an extension and discourage heavy work in the shell.

Why not a normal app window (Tauri, GTK): on GNOME Wayland a client window
cannot position itself or stay above other windows, and GNOME has no
layer-shell protocol. Only an extension can place UI in the shell's top layer.

## 3. Repository layout

The layout follows the Nara principle "build by feature, not by layer": one
folder per feature, a small public boundary, private internals, and a thin
composition layer.

```
nokta/
├── ARCHITECTURE.md          # architecture authority and locked stack
├── AGENTS.md                # instructions for coding agents
├── README.md  CONTRIBUTING.md  SECURITY.md  CODE_OF_CONDUCT.md
├── LICENSE                  # GPL-3.0-or-later
├── CHANGELOG.md             # written by release-please
├── .github/                 # issue/PR templates, CI and release workflows
├── Cargo.toml               # Rust workspace
├── contracts/               # D-Bus interface XML, the single source of truth
│   ├── io.nokta.Nokta1.xml
│   ├── io.nokta.Media1.xml
│   ├── io.nokta.Lyrics1.xml
│   └── io.nokta.Settings1.xml
├── core/                    # crate `nokta-core`, binary `noktad`
│   └── src/
│       ├── main.rs
│       ├── app/             # composition: start features, own the bus name
│       ├── features/
│       │   ├── media/       # mod.rs (public boundary), contract.rs, internals, tests
│       │   ├── lyrics/
│       │   └── settings/
│       └── shared/          # paths, cache, logging, monotonic clock
├── extension/               # GNOME Shell extension `nokta@nokta.io`
│   ├── metadata.json  package.json  tsconfig.json
│   └── src/
│       ├── extension.ts     # composition: build the notch, mount features
│       ├── features/
│       │   ├── media/       # index.ts, view.ts, client.ts
│       │   └── lyrics/
│       └── shared/          # notch shape, animation helpers, theme, D-Bus helpers
├── packaging/               # systemd user unit, D-Bus service file, install script
└── docs/
```

Rules:

- A feature exposes only what its `mod.rs` (Rust) or `index.ts` (TypeScript)
  exports. In Rust the compiler enforces this through module visibility.
- Feature dependencies are acyclic. `lyrics` depends on `media` (it needs the
  current track). `media` depends on nothing else.
- `shared/` holds business-neutral infrastructure only. No feature logic.
- A feature has the same name on both sides (`core/src/features/media` and
  `extension/src/features/media`).

### Locked stack

| Area | Choice |
|---|---|
| Daemon language | Rust (stable, edition 2021) |
| Async runtime | `tokio` |
| D-Bus | `zbus` (tokio integration) |
| HTTP | `reqwest` with `rustls` |
| Config | `serde` + `toml`, file watching with `notify` |
| Images | `image` (cover decoding for accent color) |
| Logging | `tracing` to stderr (journald captures it under systemd) |
| Extension language | TypeScript compiled with `tsc` to readable ES modules (no bundler, no minifier) |
| Extension types | `@girs/gnome-shell` and related `@girs/*` packages |
| Supported shell | GNOME Shell 46 only in v0.1 (`shell-version: ["46"]`) |
| License | GPL-3.0-or-later |

Other GNOME versions are added to `shell-version` only after they are tested.
EGO rejects extensions that claim untested versions.

## 4. The daemon (`noktad`)

### 4.1 Startup and lifetime

- Runs as a systemd user service (`nokta.service`).
- Is D-Bus activatable: `io.nokta.Nokta.service` in
  `~/.local/share/dbus-1/services/` points to the systemd unit
  (`SystemdService=nokta.service`). The first call from the extension starts
  the daemon; no autostart entry is needed.
- Owns the bus name `io.nokta.Nokta`. A second instance exits immediately.
- Event-driven only. It waits on D-Bus signals, file-watch events and HTTP
  responses. It has no polling loops.

### 4.2 Feature `media`

Tracks every MPRIS player on the session bus
(`org.mpris.MediaPlayer2.*` names) and exposes one "active player".

Active player selection:

1. A player that is `Playing` wins. If several are playing, the one that most
   recently changed to `Playing` wins.
2. Otherwise the player that was most recently `Playing` and is now `Paused`.
3. Otherwise no active player (`Available = false`).

When the active player's bus name disappears, selection runs again.

Position handling. MPRIS does not emit `PropertiesChanged` for `Position`, so
the daemon publishes a position *snapshot*: `PositionUs` read from the player,
`PositionTimestampUs` (CLOCK_MONOTONIC in microseconds when it was read) and
`Rate`. The snapshot is refreshed when playback status, rate or track changes,
when the player emits `Seeked`, and when the extension calls
`RefreshPosition()` (on notch open). The extension extrapolates the current
position from the snapshot. GJS `GLib.get_monotonic_time()` uses the same
clock, so no clock conversion is needed.

Cover art. `mpris:artUrl` may be `file://`, `http(s)://` or missing.

- `file://`: used as is.
- `http(s)://`: downloaded once to `$XDG_CACHE_HOME/nokta/art/<sha256 of URL>`,
  at most 5 MB, 10 s timeout.
- The daemon also computes an accent color from the cover (average of the
  most saturated pixels on a downscaled copy) and caches it next to the file.
- On any failure the cover is empty and the accent falls back to the theme.

Controls are forwarded to the active player: `PlayPause`, `Next`, `Previous`,
and `SetPosition` (which uses the current `mpris:trackid`, as MPRIS
requires). Capability flags (`CanGoNext`, `CanSeek`, ...) are passed through
so the UI can disable buttons.

### 4.3 Feature `lyrics`

On each track change (new `mpris:trackid`, or new title/artist when a player
reuses track ids):

1. Build a track key from normalized artist, title, album and length in whole
   seconds.
2. Look in the cache: `$XDG_CACHE_HOME/nokta/lyrics/<sha256 of key>.json`.
3. On a miss, query LRCLIB:
   `GET https://lrclib.net/api/get?artist_name&track_name&album_name&duration`.
   On 404, fall back to `GET /api/search` with artist and title and take the
   first result whose duration is within 2 seconds of the track length.
   Requests send a `User-Agent` naming Nokta, its version and the project URL,
   as LRCLIB asks clients to do.
4. Parse `syncedLyrics` (LRC format, including multiple timestamps per line
   and an optional `[offset:]` tag) into ordered `(start_us, text)` pairs.
5. Cache the result. "Not found" is cached for 7 days so the same track is not
   requested again and again.

Status values published: `none` (no track), `loading`, `synced`, `plain`,
`instrumental`, `not-found`, `error`. In v0.1 the notch shows lyrics only for
`synced`. Every other status hides the lyrics row.

Privacy: lyrics lookup sends artist, title, album and duration to lrclib.net.
It is on by default, documented in the README, and can be turned off in the
config (`lyrics.enabled = false`). Nothing else leaves the machine.

### 4.4 Feature `settings`

Reads `$XDG_CONFIG_HOME/nokta/config.toml`, writes a commented default file on
first run, watches the file and republishes on change.

Invalid file: the daemon logs the error with line and column and keeps the
last valid configuration (or the defaults if none was ever valid). It never
crashes on bad config.

v0.1 keys:

```toml
[appearance]
height = 32              # collapsed notch height in px, slightly above the 28 px top bar
idle_width = 180         # collapsed width when nothing plays
playing_width = 260      # collapsed width while music plays
expanded_width = 420
expanded_height = 150
corner_radius = 14       # bottom corners of the notch body
ear_radius = 8           # inward curves where the notch meets the top edge
background = "#000000"
foreground = "#ffffff"
use_album_accent = true  # tint progress bar and equalizer with the cover color
animation_speed = 1.0    # 0.5 = twice as fast, 2.0 = twice as slow

[behavior]
open_delay_ms = 120      # hover time before the notch opens
close_delay_ms = 300     # time after the pointer leaves before it closes
move_clock = true        # move the GNOME clock to the right side of the top bar
show_lyrics = true

[lyrics]
enabled = true           # network lookup on lrclib.net
```

Every visual value lives in this file, not in code, so later releases can add
a preferences window and themes without rewriting the UI.

## 5. The D-Bus contract (v1)

Bus name `io.nokta.Nokta`. All interfaces end in `1`. A breaking change
creates `...2` next to `...1`; it never changes `...1`.

**`io.nokta.Nokta1`** at `/io/nokta/Nokta`

| Member | Kind | Type | Meaning |
|---|---|---|---|
| `ApiVersion` | property | `u` | Contract version, `1` |
| `DaemonVersion` | property | `s` | Release version, e.g. `0.1.0` |

**`io.nokta.Media1`** at `/io/nokta/Media`

| Member | Kind | Type | Meaning |
|---|---|---|---|
| `Available` | property | `b` | An active player exists |
| `PlayerName` | property | `s` | Player identity, e.g. `Spotify` |
| `PlaybackStatus` | property | `s` | `Playing`, `Paused` or `Stopped` |
| `Title` | property | `s` | |
| `Artists` | property | `as` | |
| `Album` | property | `s` | |
| `LengthUs` | property | `x` | 0 when unknown |
| `ArtPath` | property | `s` | Local file path, or empty |
| `AccentColor` | property | `s` | `#rrggbb`, or empty |
| `PositionUs` | property | `x` | Position snapshot |
| `PositionTimestampUs` | property | `x` | CLOCK_MONOTONIC when the snapshot was taken |
| `Rate` | property | `d` | Playback rate |
| `CanPlayPause`, `CanGoNext`, `CanGoPrevious`, `CanSeek` | property | `b` | Capabilities of the active player |
| `PlayPause()` | method | | |
| `Next()` | method | | |
| `Previous()` | method | | |
| `SetPosition(x position_us)` | method | | Absolute seek |
| `RefreshPosition()` | method | | Re-read the position from the player |

**`io.nokta.Lyrics1`** at `/io/nokta/Lyrics`

| Member | Kind | Type | Meaning |
|---|---|---|---|
| `Status` | property | `s` | See 4.3 |
| `Lines` | property | `a(xs)` | `(start_us, text)`, sorted; empty unless `synced` |

**`io.nokta.Settings1`** at `/io/nokta/Settings`

| Member | Kind | Type | Meaning |
|---|---|---|---|
| `Appearance` | property | `a{sv}` | The `[appearance]` table |
| `Behavior` | property | `a{sv}` | The `[behavior]` table |

All properties emit `org.freedesktop.DBus.Properties.PropertiesChanged`.
Changes that belong together (a new track) are sent in one signal, so the UI
never shows a new title with an old cover.

## 6. The GNOME extension

### 6.1 Placement and shape

- The notch is added with `Main.layoutManager.addTopChrome()` with fullscreen
  tracking, so it sits above windows and hides when an app goes fullscreen.
- It is centered on the primary monitor and touches the top edge. It is a few
  pixels taller than the top bar, so it reads as a cut-out of the screen, not
  a widget inside the bar.
- Shape: a body with rounded bottom corners (`corner_radius`), plus two small
  "ears" at the top corners that curve inward into the top edge, like the
  MacBook notch. The ears are fixed-size drawing areas rendered once with
  Cairo and redrawn only when the config changes. The body is a plain styled
  actor, so resizing it is cheap.
- With `move_clock = true`, the GNOME date menu is moved from the center box
  to the right box of the top bar, so the calendar and notifications still
  work. `disable()` puts it back exactly where it was. When the Just
  Perfection extension is enabled, this step is skipped (see section 12).

### 6.2 States

| State | When | Content |
|---|---|---|
| Idle | No active player, or daemon unavailable | Clock (`HH:MM`, follows the GNOME 12/24 h setting) |
| Playing (collapsed) | Active player | Small cover on the left, equalizer bars on the right |
| Paused (collapsed) | Active player, paused | Small cover, bars at rest |
| Expanded | Pointer hovers the notch for `open_delay_ms` | Cover, title, artist, progress bar with times, previous / play-pause / next, current lyric line when available |

The equalizer bars are a playback indicator animated while `Playing`. They
are not a real audio spectrum (that would need PipeWire capture and is out of
scope).

### 6.3 Interaction

- Hover opens after `open_delay_ms`. Leaving closes after `close_delay_ms`.
  Re-entering during the close delay cancels the close.
- Click on buttons sends the matching method. Click or drag on the progress
  bar calls `SetPosition`. Buttons are disabled when the capability is false.
- Opening calls `RefreshPosition()` once, to correct players that report
  position loosely.

### 6.4 Animation

- Size and content changes use Clutter implicit animations on the compositor
  side (`ease()`). Starting values: open in 380 ms with
  `EASE_OUT_BACK` (a small overshoot), close in 240 ms with
  `EASE_IN_OUT_QUAD`, collapsed width changes in 300 ms with
  `EASE_OUT_QUAD`. These are tuned on the reference machine during
  implementation and always multiplied by `animation_speed`.
- Content fades and slides slightly while the body resizes, so text never
  appears clipped.
- If GNOME animations are turned off (Accessibility, "Reduce animation"), all
  transitions become instant.

### 6.5 Timers and cost

- Collapsed and idle: one timer aligned to the minute boundary for the clock.
- Playing and collapsed: only the equalizer animation.
- Expanded and playing: one timer for the progress bar and lyrics, about
  4 times per second, plus an exact timeout scheduled for the next lyric line.
- Paused, or notch hidden: no timers.

### 6.6 Talking to the daemon

- Proxies are built with `Gio.DBusProxy.makeProxyWrapper()` from the XML in
  `contracts/`, copied into the extension at build time.
- `Gio.bus_watch_name()` follows `io.nokta.Nokta`. When the name appears, the
  extension connects and reads all properties. When it vanishes, the notch
  goes to Idle. No retry loops.
- On connect the extension checks `ApiVersion`. If it is not `1`, the notch
  stays in Idle and logs one clear message telling the user to update.

## 7. Error handling

| Situation | Behavior |
|---|---|
| Daemon not installed or not running | Notch shows Idle (clock). Extension logs once. |
| Daemon crashes | systemd restarts it (`Restart=on-failure`). Notch is Idle until the name reappears. |
| No player | Idle. |
| Player closes mid-song | Selection runs again; another player or Idle. |
| Cover download fails | No cover, theme accent. |
| Lyrics not found, offline, or LRCLIB error | Lyrics row hidden. Errors are not cached, so the next track change tries again; not-found is cached for 7 days. |
| Invalid config file | Last valid config kept, error logged with location. |
| Contract version mismatch | Idle plus one log message. |
| Extension disabled | Everything it created is destroyed, every signal and main-loop source removed, the clock put back. |

## 8. Testing

Daemon (`cargo test`):

- Unit tests: active player selection, LRC parsing (multi-timestamp lines,
  offsets, malformed lines), track key normalization, cache expiry, config
  parsing and fallback to the last valid config, accent color on fixture
  images.
- Integration tests: start a private session bus (`dbus-daemon --session` in
  a temporary directory), register fake MPRIS players served by `zbus`, run
  the daemon against it and assert on `io.nokta.Media1` properties and
  signals. LRCLIB is replaced by a local HTTP stub; tests never touch the real
  network.
- Contract test: introspect the running daemon and compare each interface with
  the XML in `contracts/` after normalization. CI fails on any difference.

Extension:

- Pure logic (position extrapolation, current lyric line lookup, time
  formatting) lives in modules with no `gi://` imports and is tested with
  Node's built-in test runner.
- `tsc --noEmit` and ESLint in CI.
- UI is checked by hand in a nested shell
  (`dbus-run-session -- gnome-shell --nested --wayland`) against a written
  checklist in `docs/testing.md`: every state in 6.2, enable/disable cycles,
  fullscreen, daemon stop/start, config edit while running.

Acceptance: the success criteria in section 1, measured on the reference
machine (`ps`/`pidstat` for the daemon, `top` on `gnome-shell` with the notch
idle and open).

## 9. Keeping both sides honest

- `contracts/*.xml` is the only definition of the API.
- The Rust side implements it with `zbus` interface macros. The contract test
  in section 8 proves the implementation matches the XML.
- The TypeScript side builds its proxies directly from the same XML, plus a
  hand-written type file per interface, checked by a small script in CI that
  compares member names and types with the XML.

## 10. Release and project hygiene

- **Commits:** Conventional Commits with a real scope, for example
  `feat(media): pick the most recently playing player`.
- **Versions:** SemVer, one version for the whole repository (daemon and
  extension ship together and share the contract). `0.y.z` until the contract
  is declared stable.
- **release-please** (manifest mode) opens the release PR, writes
  `CHANGELOG.md`, bumps `Cargo.toml` and `extension/package.json`, and tags
  `v0.1.0`.
- **CI** (GitHub Actions on every push and PR): `cargo fmt --check`,
  `cargo clippy -- -D warnings`, `cargo test`, extension type check, lint and
  logic tests, contract checks.
- **Release artifacts** (built by CI when the tag is created):
  - `noktad-<version>-x86_64-linux.tar.gz`: binary, systemd unit, D-Bus
    service file, `install.sh`, `uninstall.sh`.
  - `nokta@nokta.io.shell-extension.zip`: made with `gnome-extensions pack`,
    installable with `gnome-extensions install`.
- **install.sh** installs to user locations only (`~/.local/bin`,
  `~/.config/systemd/user`, `~/.local/share/dbus-1/services`) and never uses
  sudo.
- **Repository files:** README (with screenshots, install, privacy note),
  ARCHITECTURE.md, CONTRIBUTING.md, SECURITY.md, CODE_OF_CONDUCT.md, issue
  and PR templates, AGENTS.md.
- **Not in v0.1:** publishing on extensions.gnome.org, Flatpak, distro
  packages. EGO publishing comes once the extension is stable; it will state
  clearly that the daemon is a separate download, since EGO does not allow
  binaries inside extensions.

## 11. Out of scope for v0.1

Planned for later releases, each with its own spec: focus timer, water
reminder, file shelf, to-do list, volume/brightness/caps-lock overlays,
battery/Wi-Fi/headset alerts, the idle "eyes" companion, multi-monitor,
preferences window and themes, real audio visualizer, other GNOME versions,
KDE and wlroots frontends (layer-shell), Windows, macOS, EGO and Flatpak
distribution.

## 12. Known risks

- **Just Perfection** (installed on the reference machine) also manages the
  clock position. If both move the date menu, they may fight. Rule for v0.1:
  when Just Perfection is enabled, Nokta does not move the clock itself; it
  logs one message and the README tells the user to set Just Perfection's
  clock position to the right. When Just Perfection is not enabled,
  `move_clock` applies as described in 6.1.
- **Browser players** (Chromium, Firefox) report position and track ids
  loosely. The snapshot refresh on open and on `Seeked` limits drift; lyric
  timing may still be off for some sites.
- **LRCLIB coverage** varies. Missing lyrics are expected, and the UI must
  look complete without them.
- **GNOME Shell internals** (panel boxes, date menu) are not a stable API and
  can change between versions. That is one reason v0.1 claims GNOME 46 only.
