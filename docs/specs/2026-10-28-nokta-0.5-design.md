# Nokta design: 0.5

Status: approved (Ren picked features 1, 3, 4, 5, 7 and 8 from the 0.5
suggestions and asked for them built to Claude's recommendation, without a
spec review)
Date: 2026-10-28
Scope: six parts, each its own branch and pull request, in this order:

1. Live activities: any app or script shows its progress in the notch
2. Media: shuffle, repeat and a full lyrics view
3. Weather in the idle panel
4. The next calendar event
5. The file shelf
6. Screenshot previews

Parts 5 and 6 come last because the screenshot preview can put the new
screenshot on the shelf.

## Shared changes in the extension

These land with part 1, because part 1 is the first to need them.

- **One indicator in the closed notch.** The closed notch has one spot for
  extra information: in place of the clock while idle, next to the
  equalizer while music plays (today the focus timer uses it). A pure rule
  in `shared/logic/indicator.ts` picks what goes there: the focus timer,
  else the newest running live activity, else the shelf badge, else
  nothing.
- **The idle panel grows with its content.** Today it is the date and one
  row of buttons, with a fixed height. It becomes a list of rows: the date
  line (date, then the weather from part 3), the next event (part 4), live
  activities (part 1), the shelf (part 5), then the buttons. A pure
  `panelHeight(rows)` in `panel/logic` gives the height, and
  `monitor-notch.ts` resizes the notch whenever that changes while the panel
  is open.
- `panel` keeps drawing only. `extension.ts` fills each row from the
  feature that owns it, as it already does for notifications and focus.

## 1. Live activities

### What it is

A build, a download, a backup or a deploy shows in the notch while it runs
and says how it ended. Any program can do it over D-Bus, and the `nokta`
command makes it a one-liner for scripts:

```sh
nokta run -- cargo build --release          # shows "cargo build" while it runs, then ✓ or ✗
nokta activity set backup --title "Backup" --detail "Photos" --progress 40
nokta activity end backup --message "1 204 files"
nokta activity end backup --failed --message "Disk full"
```

### Contract: `io.nokta.Activities1` at `/io/nokta/Activities`

- `Activities` (`a(ssssdx)`): id, title, detail, icon name, progress and
  start time, newest first. Progress is 0 to 1, or -1 when unknown. The
  start time is CLOCK_MONOTONIC in µs, so the extension can show the time
  elapsed.
- `Set(id s, title s, detail s, icon s, progress d)`: starts the activity or
  updates it. An empty id, an empty title or a progress outside 0 to 1 that
  is not -1 fails with `InvalidArgs`. An empty icon means a default one.
- `End(id s, success b, message s)`: removes it and emits
  `Ended(id s, title s, success b, message s, elapsed_us x)`. An unknown id
  does nothing.
- At most 8 at a time: a ninth `Set` ends the oldest as failed with the
  message `Replaced by a newer activity`.
- An activity that has not been `Set` for `activities.stale_minutes`
  (default 30) ends as failed with `No update for 30 minutes`, so a crashed
  script never leaves one behind. The service sleeps until the next stale
  deadline; nothing polls.

### Daemon

- Feature `activities`: a pure model (`model.rs`: set, end, expire, all
  taking `now`), a service task like the timer's, and `dbus.rs`.
- The `nokta` binary (`core/src/bin/nokta.rs`, Linux only) is a thin D-Bus
  client with a hand-written argument parser:
  - `nokta activity set ID --title T [--detail D] [--icon NAME] [--progress 0-100]`
  - `nokta activity end ID [--failed] [--message M]`
  - `nokta run [--title T] [--icon NAME] -- COMMAND...` runs the command
    with the terminal's stdin, stdout and stderr, shows it as an activity
    with unknown progress (the title defaults to the program name and its
    first argument), ends it with success or the exit code, and exits with
    the command's exit code. Ctrl-C reaches the command; the activity ends
    as failed. When noktad is not reachable the command still runs.
- `install.sh` and the release archive ship `nokta` next to `noktad`.

### Extension

- Feature `activities`: a client, `logic/` for the label and elapsed time,
  and views.
- The closed notch shows the newest running activity in the indicator spot:
  its icon and the percentage, or a slowly pulsing icon when the progress is
  unknown.
- The idle panel lists up to three activities: icon, title, detail, a thin
  progress bar and the elapsed time. The elapsed time ticks once a second
  only while the panel is open.
- `Ended` shows like a device alert, for `behavior.alert_duration_ms`: a
  check mark or a red cross, the title, and the message or the elapsed time
  (`Done in 1 min 32 s`). A failure is urgent.

### Settings

`[behavior] live_activities = true` (off: nothing is shown; the daemon still
accepts calls, so scripts never fail), and
`[activities] stale_minutes = 30` (1 to 1440).

## 2. Media: shuffle, repeat and a full lyrics view

The seek bar already seeks on click and drag, so this part is two things.

### Shuffle and repeat

- `io.nokta.Media1` gains `Shuffle` (`b`), `LoopStatus` (`s`: `None`,
  `Track` or `Playlist`), `CanShuffle` (`b`) and `CanLoop` (`b`), and the
  methods `SetShuffle(b)` and `SetLoopStatus(s)`. All are additions. The
  `Can...` properties are true when the player publishes the MPRIS property;
  a player without it has no button.
- The daemon reads them with the other player properties and sets them with
  `org.freedesktop.DBus.Properties.Set` on the active player.
- The expanded view gets a shuffle button left of Previous and a repeat
  button right of Next. Off is dimmed; repeat cycles None, Playlist, Track
  (with the repeat-one icon).

### Full lyrics view

- While synced lyrics are known, clicking the lyric line in the expanded
  view (or a small lyrics button next to the progress times) opens the
  lyrics view: the notch grows taller and shows seven lines around the
  current one, which is bright and slightly larger; the others are dimmed.
  The lines slide up with an ease when the current line changes.
- Clicking it again, the track changing or the notch closing returns to the
  normal expanded view.
- The window of lines is a pure function (`lyrics/logic/window.ts`): the
  current index, the lines before and after it, and the scroll offset.
- It uses the existing tick and lyric timeout; no new timers.
- Height: `expanded_height` plus 150 px.

## 3. Weather in the idle panel

- **Source:** Open-Meteo, which is free and needs no key. The daemon asks
  the geocoding API (`geocoding-api.open-meteo.com/v1/search`) for the
  configured place once, then the forecast API
  (`api.open-meteo.com/v1/forecast`) for the current temperature, weather
  code and day or night, plus today's high and low.
- **Location:** `[weather] location = ""`, a place name like `"Jakarta"` or
  coordinates like `"-6.2,106.8"`. Empty means no weather and no network
  call. `units = "celsius"` or `"fahrenheit"`. `enabled = true`.
- **No polling:** the daemon fetches at startup, when the location or units
  change, and when the extension calls `Refresh()` (the idle panel opening)
  and the last answer is older than 30 minutes, or the last failure older
  than 5 minutes. Concurrent refreshes share one request.
- **Contract:** `io.nokta.Weather1` at `/io/nokta/Weather`: `Status` (`s`:
  `off`, `loading`, `ready` or `error`), `Place` (`s`, the name the
  geocoder found), `Temperature` (`d`), `High` (`d`), `Low` (`d`), `Units`
  (`s`), `Condition` (`s`), `IsDay` (`b`); `Refresh()`. The daemon maps the
  WMO weather code to a condition: `clear`, `partly-cloudy`, `cloudy`,
  `fog`, `drizzle`, `rain`, `snow`, `showers`, `thunderstorm`.
- **Extension:** the date line becomes `Wednesday, 28 October · ☀ 31°`,
  with a symbolic weather icon (`weather-clear-symbolic`,
  `weather-clear-night-symbolic` and so on) and the place, high and low in
  a dimmed second part when there is room. Nothing shows when the status is
  not `ready`.
- Base URLs come from `NOKTA_OPEN_METEO_URL` and
  `NOKTA_OPEN_METEO_GEOCODING_URL` for tests, like `NOKTA_LRCLIB_URL`.

## 4. The next calendar event

### Source

GNOME Shell already loads calendar events for its date menu, from Evolution
Data Server through `gnome-shell-calendar-server`, so it includes online
accounts. Nokta reads that event source
(`Main.panel.statusArea.dateMenu._eventSource`, a `DBusEventSource`) with
`getEvents(now, end of tomorrow)` and its `changed` signal. Nothing new
loads, and nothing fights the date menu: the calendar server keeps one time
range for all its clients, so Nokta must not call `SetTimeRange` itself.

That makes `calendar` an extension-only feature, like `privacy` and
`notifications`. It finds the source with a feature check and stays off
when it is missing. GNOME's events only carry a title, a start and an end,
so there is no meeting link.

### What it shows

- The idle panel gets a row with the next event that has not ended: its
  title, its time (`10:30`, or `Tomorrow 09:00`), and how soon (`in 25
  min`, `now`). All-day events are left out. A click opens GNOME Calendar
  if it is installed, else the date menu.
- `reminder_minutes` before an event starts, the notch shows it like a
  device alert: the calendar icon, `Standup in 5 min`, and its time. At the
  start time it shows `Standup is starting`.
- Timers: one exact timeout for the next reminder or start, set again when
  the events change. Nothing polls.
- The date menu loads the month it shows. If the user leaves it on another
  month, the events of today may be missing until it opens again; GNOME
  resets it to today then.

### Settings

`[calendar] enabled = true`, `reminder_minutes = 5` (0 to 60; 0 = no
reminder).

## 5. The file shelf

Ren's wish: drag files from anywhere onto the notch to park them, then drag
them out again, into WhatsApp or anywhere else. An item leaves the shelf
once it has been dropped somewhere (cut, not copy). The shelf keeps
references, never copies, and lasts until logout.

### Why a helper window

GNOME Shell cannot take a drop from an app or start a drag into one; only a
normal Wayland client can. A spike (throwaway, `build/spike/`) showed on
GNOME 46 that:

- a small GTK 4 window takes file drops and drags them out again;
- the shell can spawn it as its own Wayland client (`Meta.WaylandClient`),
  make it a dock window that is not in Alt-Tab or the overview, and place
  it exactly over the notch;
- a drop on the notch reaches it when the notch and the top bar stop being
  reactive while a drag is in progress (`global.backend.get_dnd()`
  `dnd-enter` and `dnd-leave`) and become reactive again afterwards;
- the shell sees the pointer enter and leave the helper window, so the
  notch stays open while the pointer is over the shelf row.

Dragging into the real WhatsApp could not be tested in the devshell; it is
on the real-session checklist. GNOME 47 and later spawn Wayland clients
with a different call (`Meta.WaylandClient.new_subprocess`); the code
checks for the feature, not the version.

### Design

- **Daemon, feature `shelf`:** `io.nokta.Shelf1` at `/io/nokta/Shelf`:
  `Items` (`a(sss)`: URI, display name, icon name), `Add(as uris)`,
  `Remove(s uri)`, `Clear()`. It keeps the list in memory, ignores
  duplicates and non-`file://` URIs, reads the name and content type of
  each file, and watches the files' folders so a deleted or moved file
  leaves the shelf. At most 30 items.
- **Helper, `nokta-shelf`:** `extension/src/shelf-helper/main.ts`, compiled
  with the rest of the extension and run with `gjs -m`. It draws nothing
  visible itself: its window is transparent and only takes drops and starts
  drags. It reads `Items` from noktad and calls `Add` on a drop and
  `Remove` after a drag ends in a successful drop. Item positions come from
  the same pure layout function the notch uses
  (`shelf/logic/layout.ts`), so a press on the helper lands on the item the
  notch draws there. Dragging the stack icon at the start of the row drags
  every file at once.
- **Extension, feature `shelf`:** the client, the row of file icons with a
  small × on hover, the badge (a file icon and the count) in the indicator
  spot, and the helper's lifetime: spawned on `enable()` when the shelf is
  on, killed in `disable()`, and respawned at most three times if it dies.
  The helper window is placed over the whole notch while a drag is in
  progress, and over the shelf row while the notch is open with items.
- The shelf row shows under the media view and in the idle panel. While a
  drag is in progress over the notch, the notch opens with a dashed drop
  area: `Drop to keep here`.

### Settings

`[behavior] file_shelf = true`.

## 6. Screenshot previews

- GNOME shows a `Screenshot captured` notification with the screenshot as
  its image (`gicon`) after every screenshot, from the screenshot UI and
  from the direct shortcuts. Nokta's notification hook already sees it.
  When a banner comes from GNOME's screenshot source (icon
  `screenshot-recorded-symbolic`) and has an image, the notch shows a
  screenshot preview instead of the normal banner: a large thumbnail and
  three buttons, `Open`, `Show in Files` and `Keep on shelf`.
- `Open` and `Show in Files` call the notification's own activation and
  action, so GNOME does the file handling.
- `Keep on shelf` needs the file. The screenshot UI tells which file it
  saved (`Main.screenshotUI` signal `screenshot-taken`); the direct
  shortcuts do not, so the button only shows when the file is known.
- It stays for `notifications.duration_ms` and pauses while the pointer is
  on it, like a notification.
- `[behavior] screenshot_preview = true`. It needs `notifications.in_notch`;
  with that off GNOME shows its own banner.

## Settings window

Every new key gets a row in `features/settings/logic/schema.ts`: Live
activities and the shelf under Behavior, a Weather group (enabled,
location, units), a Calendar group (enabled, reminder), and the stale time
under Live activities. `io.nokta.Settings1` gains the `Activities`,
`Weather` and `Calendar` properties, and `Set` accepts those tables.

## Testing

- Daemon: unit tests for each pure model (activities, weather codes and
  freshness, shelf list), wiremock tests for Open-Meteo, integration tests
  on a private bus for every new interface, the contract test for each XML,
  and a test that `nokta run` passes the exit code through.
- Extension: Node tests for every `logic/` module (indicator choice, panel
  height, activity labels, lyric window, shelf layout, next event and
  reminders, weather icons, screenshot detection).
- Devshell smoke test, on GNOME 46 to 51 in CI: an activity shows and ends;
  shuffle and repeat buttons with a fake player that has them; the lyrics
  view opens; the weather line with a fake Open-Meteo server; a calendar
  row from a fake event source; the shelf helper spawns, a drop reaches it
  and the badge shows; a fake screenshot notification shows the preview.
- Real session, by Ren: drag a file from Files onto the notch and into
  WhatsApp; a real screenshot; a real calendar event.
