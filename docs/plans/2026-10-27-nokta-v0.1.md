# Nokta v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Nokta v0.1.0: a Rust daemon (`noktad`) that tracks MPRIS players and synced lyrics, plus a GNOME Shell 46 extension that draws a MacBook-style notch with music controls and the current lyric line.

**Architecture:** `noktad` owns all logic and I/O and serves the versioned `io.nokta.*` D-Bus interfaces defined in `contracts/*.xml`. The extension (TypeScript compiled by `tsc` to readable ES modules) only draws, animates and forwards clicks. Features live in one folder per feature on both sides (`media`, `lyrics`, `settings`), composed by `core/src/app` and `extension/src/extension.ts`.

**Tech Stack:** Rust stable, tokio, zbus 5 (tokio), reqwest (rustls), serde + toml, notify, image, sha2, rustix, tracing; TypeScript, `@girs/gnome-shell` 46 types, ESLint (typescript-eslint), Node's built-in test runner.

**Spec:** `docs/specs/2026-10-27-nokta-v0.1-design.md`

## Global Constraints

- GNOME Shell 46 only: `metadata.json` has `"shell-version": ["46"]`.
- Extension UUID `nokta@nokta.io`. Bus name `io.nokta.Nokta`. Interfaces `io.nokta.Nokta1`, `io.nokta.Media1`, `io.nokta.Lyrics1`, `io.nokta.Settings1` at `/io/nokta/Nokta`, `/io/nokta/Media`, `/io/nokta/Lyrics`, `/io/nokta/Settings`. `ApiVersion = 1`.
- License GPL-3.0-or-later in every package manifest and `LICENSE`.
- Extension JS is produced by `tsc` only: no bundler, no minifier. No binaries inside the extension.
- The daemon never polls. It only reacts to D-Bus signals, file-watch events and HTTP responses.
- Daemon idle: 0 % CPU, under 15 MB RSS.
- Extension timers: idle = one minute-aligned clock timer; paused or hidden = none; expanded and playing = ~250 ms tick plus one exact timeout for the next lyric line.
- Config path `$XDG_CONFIG_HOME/nokta/config.toml` (fallback `~/.config`). Cache `$XDG_CACHE_HOME/nokta/{art,lyrics}` (fallback `~/.cache`).
- Config defaults (exact): `height 32, idle_width 180, playing_width 260, expanded_width 420, expanded_height 150, corner_radius 14, ear_radius 8, background "#000000", foreground "#ffffff", use_album_accent true, animation_speed 1.0, open_delay_ms 120, close_delay_ms 300, move_clock true, show_lyrics true, lyrics.enabled true`.
- Animations: open 380 ms `EASE_OUT_BACK`, close 240 ms `EASE_IN_OUT_QUAD`, collapsed width change 300 ms `EASE_OUT_QUAD`, all multiplied by `animation_speed`; instant when GNOME animations are off.
- LRCLIB base URL `https://lrclib.net`, duration tolerance 2 s, not-found TTL 7 days (604800 s), `User-Agent: Nokta/<version> (https://github.com/MasRama/nokta)`.
- Cover download: max 5 MB, 10 s timeout.
- Commits: Conventional Commits with a real scope, one commit per unit of change, no AI attribution trailers.
- Heavy commands (`cargo build/test/clippy`, `npm install`, `tsc`, headless gnome-shell) run one at a time.

## Review Focus

1. **Player with missing metadata** (browser tab with no title, no artist, no length): no crash; UI shows `PlayerName` as the title; progress bar hidden when `LengthUs == 0`. Pinned in Task 6 (`track_from_empty_metadata`) and Task 11 (position logic with length 0).
2. **Track changes while a lyrics lookup is in flight**: the late result for the old track must never replace the new track's lyrics. Pinned in Task 8 (`stale_lookup_is_discarded`).
3. **Track length unknown (0) when looking up lyrics**: skip `/api/get`, use `/api/search` and take the first synced result without a duration filter. Pinned in Task 5 (`zero_duration_uses_search_without_filter`).
4. **Config replaced by an editor (write-to-temp + rename) or deleted while running**: rename reloads; deletion keeps the current config. Pinned in Task 3 (`deleted_file_keeps_last_valid`, watcher test on rename).
5. **`file://` cover URLs with percent-encoded characters** (spaces, unicode): decoded to a real path. Pinned in Task 7 (`file_url_is_percent_decoded`).

### Task 4: LRCLIB client
