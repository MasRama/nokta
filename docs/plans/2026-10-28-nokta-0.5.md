# Nokta 0.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship live activities, shuffle/repeat and a lyrics view, weather,
the next calendar event, the file shelf and screenshot previews.

**Architecture:** Daemon features `activities`, `weather` and `shelf` with
new `io.nokta.*1` interfaces; additions to `Media1` and `Settings1`;
extension-only `calendar` and `screenshots`; a GTK 4 helper for the shelf.

**Tech Stack:** Rust (tokio, zbus, reqwest, notify), TypeScript for GNOME
Shell 46 to 51 and GTK 4 (helper), Node tests, devshell smoke test.

**Spec:** `docs/specs/2026-10-28-nokta-0.5-design.md`

## Global Constraints

- Contracts first: XML in `contracts/`, then daemon, `contracts.ts`, tests.
- Additions only to published `...1` interfaces.
- Tests first; extension decisions in `logic/`, tested with Node.
- No network, file I/O, subprocess (except the shelf helper as a Wayland client) or polling in the shell process.
- Every actor, signal and source made in `enable()` is removed in `disable()`.
- Heavy commands one at a time.
- One branch and pull request per part; GNOME 46 to 51 CI green before merging.
- Conventional Commits with a real scope; no AI attribution.
- `ARCHITECTURE.md` updated in the same branch as each feature.

## Review Focus

- `nokta run` when noktad is missing: the command still runs and its exit code passes through (test in Task 1.2).
- An activity script that dies without `End`: the stale deadline ends it (test in Task 1.1).
- Weather with an unknown place name: status `error`, no retry storm (test in Task 3.1).
- A shelf file deleted while parked: it leaves the shelf (test in Task 5.1).
- A player without `Shuffle`/`LoopStatus`: no buttons, no failing calls (test in Task 2.1).
